# Application-wide interface refinement

The champion is i004, Exception-led metadata with stable details. The record contains 100 candidate mechanisms, 99 individual matches and seven rounds. Three author batches produced the ideas; 63 matches were judged by delegated non-authors and 36 by the root non-author after worker usage limits. These are 100 proposals, not 100 Claude executions. Synthetic judgments are hypotheses, not measured user preference. Ranking uses tied elimination stages; scores from different matches are not comparable global ratings.

## Main direction and compatible proposals

- i004: preserve visible overdue/divergent dates, selected reference period and actual inclusion scope. Task Details provides metadata and a stable edit route even when empty. List and section information disclosures appear where there is information to inspect; empty statistics do not create an empty extra control. This narrows the winner’s blanket stable-route promise to meaningful content at those scopes, while preserving existing options.
- i027: semantic native disclosure, keyboard access and scoped accessible names.
- i044: steady local information placement; management Options share the collapsed name row and expand commands only when requested.
- i016: one factual count rather than repeated progress graphics. Mixed own/included completion remains visible because it affects action.
- i052 and i062: keep exact period and included frequency scope visible; recurrence origin is not a missed-task claim.
- i100 and i084: explicit responsive section menus, 44px controls, names tied to the object, focus containment and restoration.
- i033: preserve Start, completion, skips, all edit fields and original business operations.

## Ranked weaknesses and repairs

1. Keyboard operation and action reachability: native account buttons, named drawer inputs, topmost-sheet focus and Escape, independent duration editing, unchanged original callbacks.
2. Misleading or excessive context: retain relevant dates and period/scope, disclose optional metadata, preserve past-period section history from the baseline.
3. Organization effort: fold five per-list commands into Options; move color/icon choice after primary configuration; group device preferences.
4. Secondary workflow noise: reveal shared notes, integration instructions and export format choices on demand. Primary completion, creation, save/cancel and backup remain direct.
5. Repeated presentation: compact page/section context rows, single routine status and actual touch geometry.

Every retained surface and audit scope is recorded in modal-audit.json and screen-audit.json. The independent review found management density, duration routing and empty task Details issues; all three were repaired. The review snapshots explicitly precede the final build. Final verification is recorded in verification.md.

## Design evidence

Apple HIG recommends clear hierarchy and disclosure of secondary content: [Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Disclosure controls](https://developer.apple.com/design/human-interface-guidelines/disclosure-controls) and [Context menus](https://developer.apple.com/design/human-interface-guidelines/context-menus). Glass is used for navigation and overlays, with legible content surfaces and reduced-motion behavior retained. No product usage telemetry was available; option ordering is an explicit task-value hypothesis, not a claim about which users click most.
